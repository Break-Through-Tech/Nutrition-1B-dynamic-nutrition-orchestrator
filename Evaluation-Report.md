# Evaluation Report

## 1. Project summary

This project is a nutrition-planning system for high-protein Indian vegetarian meal planning. The repository description frames it as a Tool-Augmented Generation (TAG) system that combines local recipe templates with USDA nutrition data and a deterministic arithmetic layer to prevent hallucinated macro calculations.

## 2. Project objective and challenge framing

The project aims to automate meal planning under strict dietary constraints while keeping the arithmetic deterministic and grounded in verified nutrition data. The original challenge states three success criteria:

1. Macro Optimization Precision: Mean Absolute Error (MAE) below 2% across a full 7-day generation cycle.
2. Entity Resolution Accuracy: F1-score above 90% on an unseen validation set of 30 common Indian vegetarian ingredients.
3. Scheduling Constraint Adherence: 100% compliance with zero-repeat ingredient logic across any consecutive 48-hour block.

## 3. What the project builds

The repository describes the following implementation components:

- A local recipe seed database built from source recipe documents and stored in normalized JSON and CSV outputs.
- A deterministic macro engine that calculates calories, protein, carbohydrates, and fat from canonical per-100g values.
- Dietary restriction filtering for vegetarian, vegan, dairy-free, nut-free, and gluten-free meal selection.
- Ingredient resolution against USDA FoodData Central records using a local snapshot and validation set.
- A reproducible evaluation flow that saves USDA candidates to disk and evaluates against a labeled validation CSV instead of depending on a live API.

## 4. Data sources and repository evidence

The repository includes the following data artifacts:

- Local recipe bank: [data/recipes.json](data/recipes.json)
- Ingredient catalog: [data/ingredients.csv](data/ingredients.csv)
- USDA candidate snapshot: [data/usda_candidates.json](data/usda_candidates.json)
- Validation set for matcher evaluation: [data/validation_set.csv](data/validation_set.csv)
- USDA raw data tables in the [data/](data/) directory

## 5. Implementation areas in the codebase

The current implementation is organized across the following files:

- [build_recipe_db.py](build_recipe_db.py): builds the local recipe database
- [src/nutrition_engine/macro_math.py](src/nutrition_engine/macro_math.py): calculates nutrition totals from canonical ingredient records
- [src/nutrition_engine/scaling.py](src/nutrition_engine/scaling.py): scales ingredients and recipes to serving or target constraints
- [src/nutrition_engine/meal_planner.py](src/nutrition_engine/meal_planner.py): enforces restrictions and plans meal options
- [src/nutrition_engine/ingredient_matcher.py](src/nutrition_engine/ingredient_matcher.py): normalizes ingredient names, applies synonyms, and scores USDA candidates
- [src/nutrition_engine/matcher_eval.py](src/nutrition_engine/matcher_eval.py): evaluates match quality against a validation set
